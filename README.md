## 🚀 미션 진행 방식

프로젝트 세팅과 주차별 미션은 **반드시 본인 개인 폴더에서만 진행**합니다.
개인 폴더 내 **파트별로 따로 분리해서 올려주세요**

예시: `Suhhee/FE` `Suhhee/BE`

### 💡 진행 순서

1. **Issue 생성** <br>
   주차 별로 진행할 미션에 대해 이슈를 생성합니다.

2. **Branch 생성**<br>
   생성한 Issue를 기준으로 개인 브랜치를 생성합니다.

3. **작업 진행**<br>
   **본인 폴더 내부에서만** 진행합니다.
   다른 스터디원의 폴더는 **절대** 수정하지 않습니다.

4. **Pull Request 생성**<br>
   작업이 끝나면 PR을 올립니다.
   PR 본문은 저장소에 설정된 PR 템플릿 양식에 맞춰 작성합니다.
   PR은 반드시 본인 브랜치를 대상으로 작성합니다.

### 💡 작업 범위 규칙

- ✅ 본인 폴더 내 미션 코드 작성
- ✅ 본인 폴더 기준 리팩토링, 테스트, 문서 보완
- ❌ 다른 사람의 개인 폴더 수정
- ❌ 공통 구조를 임의로 변경하는 작업
- ❌ 다른 사람의 브랜치로 pr 작성

## 💻 Commit Message Convention
| **Type** | **Description** |
| --- | --- |
| **Feat** | 새로운 기능 추가 |
| **Fix** | 버그 수정 |
| **Docs** | 문서 수정 |
| **Style** | 코드 formatting, 세미콜론 누락, 코드 자체의 변경이 없는 경우 |
| **Refactor** | 코드 리팩토링 |
| **Test** | 테스트 코드, 리팩토링 테스트 코드 추가 |
| **Chore** | 패키지 매니저 수정, 그 외 기타 수정 (예: .gitignore) |
| **Design** | CSS 등 사용자 UI 디자인 변경 |
| **Comment** | 필요한 주석 추가 및 변경 |
| **Rename** | 파일 또는 폴더 명을 수정하거나 옮기는 작업만인 경우 |
| **Remove** | 파일을 삭제하는 작업만 수행한 경우 |
| **Init** | 프로젝트 초기 세팅 |
| **Merge** | 브랜치 merge |
| **!BREAKING CHANGE** | 커다란 API 변경의 경우 |
| **!HOTFIX** | 급하게 치명적인 버그를 고쳐야 하는 경우 |
> Type: commit title
>
> ex. `Feat: 로그인 기능 추가`
